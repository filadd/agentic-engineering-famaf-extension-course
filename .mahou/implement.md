# Implement in kurasu

- **Tracker**: an Entire trail per change, created with `entire trail create --no-branch --type feature`. The trail's description holds the change's tasks as a markdown checklist, one `- [ ]` line per task with what it requires. There is no local task list.
- **Reaching it**: `entire trail show <P> --json` reads the description; `entire trail update <P> --body "…"` writes it, and replaces the whole description, so read it first and write it back whole.
- **States**: a task is pending as `- [ ]` and done as `- [x]`. It is marked done when its change is implemented, tested and committed. There is no in-progress state. The trail goes to `--status closed` when its branch is merged.
- **Description format**: Entire stores the description as plain text: it drops list dashes, bold, backticks, headings and blank lines, and keeps the `[ ]`/`[x]` marks. It keeps line breaks only when the body is written as a markdown list: write each task as `- [ ] <task>`, with a blank line around the `Tareas` heading line. A body of bare `[ ]` lines comes back as one paragraph.
- **Branch**: the trail is created without a branch. Once the change's branch is pushed, and before its pull request is opened, link it with `entire trail link <P> --branch <branch>`. A pull request whose branch belongs to no trail makes Entire create a new trail for it.
- **Sessions on the trail**: a trail shows the checkpoints of its branch, and a checkpoint is a session attached to a commit through an `Entire-Checkpoint` trailer. Entire records no session on its own during an implement run. Every subagent inherits `ENTIRE_PI_NESTED=1` from the supervisor, and the project's Entire extension for pi then forwards nothing, so the subagents' commits carry no trailer. The supervisor runs on `main` and commits nothing on the branch. When the run ends, before the branch is pushed, attach every session from a checkout on the branch:
  - Each subagent's transcript stays in `~/.pi/agent/sessions/--<worktree path with / as ->--/` after its worktree is removed; the first user message of each names its job.
  - Attach each subagent to the last commit it made: `entire session attach <id> --agent pi --commit <sha> --force`. Attach the reviewers a review dispatched, and the review session itself, to the review's last commit with `--review`. A session that made no commit goes on the commit of the stage it served.
  - Attach the supervisor last, to the branch's last commit: `entire session attach $PI_SESSION_ID --agent pi --commit <sha> --force`.
  - Each attach to a commit without a checkpoint rewrites that commit and every later one; the content stays. Look up each commit by its subject, not by an earlier hash. A second session on the same commit joins its checkpoint without a rewrite.
  - Without a terminal, `attach` only prints what it would do; `--force` applies it. This rule is the user's go-ahead for unpushed commits on the change's branch.
  - The sessions show on the trail once the branch is linked.
- **Closing**: close the trail with `entire trail update <P> --status closed` once its pull request is merged.

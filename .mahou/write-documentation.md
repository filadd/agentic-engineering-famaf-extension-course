# Writing documentation in kurasu

- When a change's prototype shows a screen that already has a prototype in `app/docs/prototipos/`, update that existing prototype with the new functionality instead of adding a new file. Keep its file name, its states and its controls, add the change's states and interactions to them, and update its row in `prototipos/README.md` when what it shows changes. Add a new prototype only for a screen that has none.

## Demo 2: subagents extension

**Type-check** against Pi 1.6's own types, using a throwaway tsconfig in the scratchpad that points the imports at `/usr/lib/node_modules/pi/node_modules`: before the fix it reported one error.
```
subagents.ts(88,3): error TS2353: ... 'modelRegistry' does not exist in type 'CreateAgentSessionOptions'.
```
The CHANGELOG confirms it: "Replaced the SDK's `CreateAgentSessionOptions.authStorage` and `modelRegistry` options with the async `modelRuntime` option". `ctx.modelRegistry` keeps its runtime private, so the extension cannot pass the parent's runtime to the child.

**Fix:** I removed the `modelRegistry` option, with a comment saying why, and dropped it from the two `Pick&lt;ExtensionContext, …&gt;` types. When the option is missing, the child builds its own `ModelRuntime` from the same agent directory (auth.json and models.json), so it uses the same credentials. One limit: a key given only through `--api-key` on the parent would not reach the child. In plain JS the old option was silently ignored, so this mainly fixes the type error. After the fix, tsc exits 0.

**Other APIs:** these all type-check and are still documented the same way in `docs/extensions.md` and `docs/sdk.md`:
- `createAgentSession`, `DefaultResourceLoader` (`systemPromptOverride`, `appendSystemPromptOverride`, `reload()`), `SessionManager.inMemory`, `SettingsManager.inMemory`, `getAgentDir`
- `registerTool` with `promptSnippet`, `promptGuidelines`, `renderCall`, `renderResult`
- `registerMessageRenderer`, and `sendMessage` with `deliverAs: "followUp"` and `triggerTurn`
- `typebox`, which is still a supported import (1.3.27 ships with Pi)
